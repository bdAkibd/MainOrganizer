MineOrganizer User Manual

MineOrganizer is a desktop manager for Minecraft game environments, mods, saves, resource packs, shaders, profiles, configuration files, and backups. It brings files from different launchers into one workspace and helps you switch complete sets of content safely.

What the program is for

Use MineOrganizer when you have several Minecraft installations or mod collections and want to:

  • see environments from Prism Launcher, CurseForge, the official launcher, TLauncher, and legacy installations;
  • keep one searchable library of mod JAR files and select compatible mods for a profile;
  • store and install worlds through the saves folder without opening the game directory manually;
  • apply profiles containing mods, resource packs, and shaders;
  • check an environment before changing it and roll back managed links when needed;
  • create backups of configuration files and restore them later.

Safety: preview and environment checks are read-only. Close Minecraft before applying a profile, installing assets, restoring backups, or changing files in an active environment.

First launch

  1. Open Settings → Language selection and choose the interface language. English is the default for a new installation; the choice is saved automatically.
  2. Choose a light or dark theme from View. The theme is also saved automatically.
  3. Open Game environments and press Refresh. MineOrganizer searches known launcher locations.
  4. If an installation was not detected, use Add game folder, Choose Prism folder, or create an instance for the official launcher.

Game environments

This table lists the folders that MineOrganizer can manage. It shows the source, environment name, Minecraft version, loader, loader version, and current status.

  • Prism Launcher: instances are read from the configured Prism directory.
  • CurseForge: instances are read from %USERPROFILE%\curseforge\minecraft\Instances.
  • Legacy and other installations: version and loader information may be read from the folder name or JSON metadata.

Use the context menu on a row to open its folder or perform an available environment action. Refresh after installing or removing an instance outside the program.

Mod library

  1. Press Import JAR and select one or more mod files. The original files are copied into the library.
  2. Use the filters to narrow the list by Minecraft version, loader, or compatibility.
  3. Open the context menu for an item to inspect it, remove it from the library, or assign it to a profile where supported.
  4. Press Refresh library after changing library files outside MineOrganizer.

Version detection first uses mod metadata. If metadata is incomplete, the program also examines the file name, including patterns such as mc1.20.1, 1.20.1-forge, dynamiclights-1.20.1.2, and +1.20.1. A mod can list several Minecraft versions; these are treated as one mod entry with multiple compatible versions, so choosing one profile version does not create duplicate versions.

Manual Minecraft-version override

Automatic detection is only a best effort. If the Minecraft version shown for a mod is incorrect, select the mod in the library and use Edit Minecraft version… from the toolbar or the context menu.

  • Enter one version, for example 1.20.1.
  • Enter several versions separated by commas, for example 1.20.1, 1.21.
  • Version ranges such as [1.20,1.21) are also accepted.
  • Leave the field empty to clear the override and return to automatic detection.

The override is saved for that exact file and remains after restarting the program. It is used by the library table, version filters, profile mod selection, and compatibility checks. It does not modify the JAR file itself.

Saves

The Saves tab manages Minecraft worlds for the selected environment.

  1. Select an environment or profile.
  2. Import a world archive or world folder into the save library.
  3. Choose the world and install it. MineOrganizer places it in the environment's saves directory.
  4. Use the context menu to open, remove, or refresh library entries.

Back up important worlds before replacing an existing save with the same name.

Profiles

A profile is a named selection of mods and related assets for one game environment.

  1. Choose the target environment in Instance for new profile.
  2. Press Create profile and enter a name.
  3. Select a profile in the table and press Edit mods to choose compatible mods. A mod supporting several versions can still be selected once for the chosen Minecraft version.
  4. Use Rename or Delete profile to maintain the list.

Applying a profile

  1. Select the profile in the virtualization section.
  2. Press Preview and review every proposed action.
  3. Press Apply profile only after the preview is correct.
  4. Use Rollback last application to undo the most recent managed change.
  5. Use Check conflicts if files in the target folder were changed manually.

MineOrganizer manages links for selected files so one library can serve several profiles. It does not overwrite unrelated regular files.

Environment check

This tab inspects a selected environment and reports detected Minecraft files, loader information, external mods, and compatibility details. It is useful before creating a profile or diagnosing why a mod is not available. The check does not modify the environment.

Resource packs and shaders

  1. Select Resource packs or Shaders.
  2. Press Import ZIP to copy an archive to the separate asset library.
  3. Select a profile and press Choose for profile if the asset should be included.
  4. Use Preview, Apply assets, and Rollback assets in the same way as profile virtualization.

Assets are linked into the environment's resourcepacks or shaderpacks folder. Existing regular files are not overwritten.

Configs and backups

The table shows available configuration files and backups instead of leaving the page empty.

  • Use Backup to create a timestamped archive of the selected environment's config folder.
  • If the environment has no config folder, the program reports that fact and does not create a misleading archive.
  • Select an existing backup and use Restore to put the configuration back. Close Minecraft first.
  • Refresh the table after adding or deleting archives outside the program.

Recommended workflow

  1. Refresh and verify the target environment.
  2. Import mods, saves, resource packs, and shaders into their libraries.
  3. Create a profile for the environment.
  4. Select compatible content and preview the planned changes.
  5. Create a configuration backup before a large change.
  6. Close Minecraft, apply the profile, then start the game and test it.
  7. If something is wrong, close the game and use rollback or restore.

Troubleshooting

  • An environment is missing: refresh, select the correct launcher folder, or add the game directory manually.
  • A mod has no version: verify that its version is present in metadata or its file name; refresh the library after renaming or replacing it.
  • A mod is filtered out: check the selected environment's Minecraft version and loader.
  • Applying fails: close Minecraft, inspect the preview, check conflicts, and verify that the target folder is writable.
  • A backup is unavailable: refresh the Configs and backups tab and check that the archive belongs to the selected environment.

Important limitations

MineOrganizer manages files that it can identify and link. It does not install Minecraft loaders, download mods from online services, or guarantee that a third-party mod is compatible. Always keep independent backups of irreplaceable worlds and configurations.
