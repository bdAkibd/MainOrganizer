# MainOrginizer

## Версия 0.16.0

- Архив исходников не содержит виртуальных окружений, кэшей Python и файлов сборки. Зависимости устанавливаются отдельно.
- Добавлен `run_windows.bat` для запуска приложения из исходников без сборки EXE. Зависимости сохраняются в `.venv-dev` и не устанавливаются заново при каждом запуске.
- Локальная сборка через `build_windows.bat` переиспользует окружение `.venv-build` и кэш PyInstaller: убран принудительный `--clean`, чтобы повторные сборки выполнялись быстрее.
- GitHub Actions теперь прикрепляет `MainOrginizer.exe` к GitHub Release при отправке тега вида `v0.16.0`; ручной запуск workflow по-прежнему создаёт скачиваемый артефакт.
- Сборка EXE отделена от обычной разработки: при изменении кода можно запускать `run_windows.bat`, а EXE создавать только для тестовых или стабильных релизов.

### Разработка на Windows

1. Установить Python 3.12 или новее с сайта python.org.
2. Запустить `run_windows.bat`. При первом запуске создастся `.venv-dev` и установится PySide6; последующие запуски используют это окружение.
3. Для проверки тестов выполнить `.venv-dev\Scripts\python.exe -m unittest discover -v`.
4. Для локальной сборки EXE запустить `build_windows.bat`. Готовый файл будет в `dist\MainOrginizer.exe`.

### Публикация релиза через GitHub

После публикации репозитория отправьте тег `v0.16.0` в GitHub. GitHub Actions запустит тесты, соберёт Windows EXE и добавит его к релизу. Если workflow запустить вручную через Actions, EXE появится в Artifacts, но новый Release не создаётся.

## Запуск исходного кода на Windows

Требуется Python 3.12+ для сборки EXE (для запуска исходного кода подойдёт совместимая версия Python).

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

Тесты:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -v
```

## Сборка автономного EXE на Windows

1. Установите Python 3.12 с сайта https://www.python.org/downloads/windows/. Это нужно только разработчику для сборки, а не друзьям для запуска готового EXE.
2. Распакуйте проект и запустите `build_windows.bat`.
3. После успешных тестов и сборки файл появится в `dist\MainOrginizer.exe`. Передайте друзьям только этот EXE.

Готовый EXE содержит Python и зависимости приложения. Первый запуск может занять больше времени из-за распаковки. Windows SmartScreen или антивирус могут предупреждать о самостоятельно собранном файле без цифровой подписи. Не отключайте защиту Windows ради запуска; сначала проверьте источник файла.

Если проект размещён на GitHub, workflow **Build Windows executable** можно запустить вручную во вкладке Actions. Готовый EXE появится среди артефактов запуска workflow.

## Данные

Библиотека модов по умолчанию: `%LOCALAPPDATA%\MainOrginizer\library\mods`.
Пользовательские метки и профили: `%LOCALAPPDATA%\MainOrginizer\user_data.json`.
На других ОС используется `~/.local/share/MainOrginizer/`.

## Ресурспаки, шейдеры и конфиги

1. Во вкладке «Ресурспаки и шейдеры» выберите категорию и импортируйте ZIP-архивы. Оригиналы не перемещаются.
2. Выберите профиль и нажмите «Выбрать для профиля…» для нужной категории.
3. Изучите предпросмотр и только затем применяйте ссылки. Обычные файлы не перезаписываются; при конфликте применение блокируется.
4. Для отката используйте «Откатить ассеты». Управляются только ссылки MainOrginizer.
5. Во вкладке «Конфиги и резервные копии» выберите экземпляр и создайте архив папки `config`.
6. Перед восстановлением закройте Minecraft. Программа сначала сохранит текущие конфиги. Файлы, отсутствующие в выбранном архиве, не удаляются.

Архивы ассетов пока поддерживаются в формате ZIP. Папки конфигураций резервируются, но не входят в автоматическое переключение профилей.

## Виртуализация профилей

1. Импортируйте несколько тестовых JAR в библиотеку и создайте профиль с ними.
2. Откройте «Виртуализация», выберите профиль и нажмите «Предварительный просмотр».
3. Убедитесь, что программа предлагает создать ссылки только на отмеченные моды.
4. Закройте Minecraft, нажмите «Применить профиль» и проверьте ссылки в папке `mods`.
5. Измените состав профиля и примените его повторно: управляемые ссылки должны обновиться, обычные файлы — остаться.
6. Нажмите «Откатить последнее применение» и проверьте восстановление предыдущего состояния.
7. Проверьте конфликт: положите обычный файл с именем выбранного мода в `mods`. Применение должно быть заблокировано, файл не должен измениться.

Не тестируйте сначала на важном игровом экземпляре. Используйте копию экземпляра Prism.

## Подключение официального Minecraft Launcher

1. Нажмите «Создать сборку для Minecraft Launcher…».
2. Введите имя, например `Fabric-1.21.1`. MainOrginizer создаст `.minecraft/instances/Fabric-1.21.1` и необходимые каталоги.
3. В официальном лаунчере откройте «Установки», выберите нужную установку → «Изменить» и укажите полный путь к созданной папке в поле «Каталог игры».
4. Установите Forge/Fabric/NeoForge для выбранной установки обычным способом. MainOrginizer управляет файлами модов, но не устанавливает загрузчик.

## Подключение TLauncher / Legacy Launcher

1. Откройте лаунчер и найдите функцию открытия папки игры.
2. В MainOrginizer нажмите «Добавить папку TLauncher / Legacy…» и выберите именно игровой каталог, содержащий `versions`, `mods`, `assets` или `libraries`.
3. Если в Legacy Launcher включены отдельные подпапки для версий, выберите папку нужной версии, открыв её через сам лаунчер. Если используете общий `.minecraft` с несколькими версиями, MainOrginizer покажет, что версий несколько.
4. Проверьте распознанные версию и загрузчик перед созданием профиля.
5. Отключение подключённой папки удаляет только запись из MainOrginizer, а не сами файлы.

## Проверка новой версии

1. Откройте «Проверка окружений» и нажмите «Проверить окружения». Убедитесь, что JAR-файлы в папках `mods` отображаются.
2. Добавьте тестовый `.jar` в папку `mods` одного экземпляра Prism и повторите проверку: он должен отображаться как внешний, если его содержимого нет в библиотеке.
3. Убедитесь, что проверка не перемещает и не удаляет файлы.

## Метки и профили

1. Откройте «Библиотека модов», выберите JAR и нажмите «Изменить метки».
2. Перезапустите приложение и убедитесь, что метки сохранились.
3. На вкладке «Профили» создайте профиль, отметьте моды и проверьте редактирование, переименование и удаление.
4. Без применения профиля файлы Minecraft не меняются.

## Структура

- `main.py` — запуск.
- `ui/` — интерфейс.
- `launchers/prism/` — обнаружение и чтение экземпляров Prism.
- `launchers/game_directory/` — автообнаружение игровых папок Minecraft Launcher, TLauncher и Legacy Launcher.
- `models/` — модели данных.
- `services/mod_library.py` — библиотека модов.
- `services/environment_scan.py` — read-only проверка модов в экземплярах.
- `services/virtualization.py` — предварительный просмотр, создание ссылок на моды и откат.
- `services/asset_library.py` — библиотеки ресурспаков и шейдеров.
- `services/asset_virtualization.py` — применение ассетов и откат ссылок.
- `services/config_backups.py` — резервные копии и восстановление конфигов.
- `services/user_data.py` — сохранение тегов и профилей.
- `tests/` — автоматические тесты.

## План

1. Сканирование Prism и библиотека модов.
2. Профили и метки.
3. Read-only сканирование внешних файлов (готово).
4. Виртуализация модов с предварительным просмотром, проверками и откатом (готово).
5. Ресурспаки, шейдеры и резервные копии конфигов (базовая версия готова).
6. Улучшение метаданных, проверка конфликтов и совместимости (базовая версия готова); поддержка других лаунчеров.

Git хранит историю кода, но не заменяет резервные копии игровых файлов. Не добавляйте пользовательские данные, токены или игровые каталоги в репозиторий.
